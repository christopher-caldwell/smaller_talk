# UI review after workspace migration

Reviewed the running native app with the migrated existing conversation on October 19, 2026. The existing Markdown table now renders correctly. Model discovery lists both authenticated providers. Search has a clear no-results state. No messages were sent during this review, and no conversation content or model settings were changed.

These are follow-up improvements to existing controls, not proposals for additional product features.

| Priority | Finding | Improvement |
| --- | --- | --- |
| High | Native accessibility inspection exposes only the window and macOS controls, not the chat controls. | Expose meaningful roles, names, values, and focus for navigation, composer controls, and messages. Visual labels alone are insufficient. |
| High | Model and effort choices appear in a large centered modal that dims and covers the conversation. | Anchor compact menus above the clicked composer control, constrain them to the window, and retain scrolling for long lists. |
| High | Popup choices are implemented as click handlers without menu keyboard selection. | Add arrow-key navigation, Enter selection, visible focus, and reliable Escape dismissal; prevent underlying composer input while a menu owns focus. |
| Medium | Effort choices show raw lowercase identifiers and no checkmark for the current choice. “Default effort” does not explain the effective default. | Show readable labels, mark the selected option, and show the discovered default when the provider supplies it. Keep protocol identifiers internal. |
| Medium | Search has no visible clear control; returning from an empty result requires manually deleting text. | Add a clear button and predictable Escape behavior that restores the chat list and returns focus. |
| Medium | The migrated chat is still named “Untitled,” so both its tab and sidebar row offer little recognition. | Show a non-destructive first-message fallback when the stored title is empty or Untitled; preserve explicit user titles. |
| Medium | The model picker marks selection but its composer label does not explicitly identify the provider. Chat/Plan appears as bare text with little explanation. | Improve selected/hover states and concise tooltips for provider, effort, and mode without adding permanent visual clutter. |

Start with accessibility/focus and anchored menus, then selection feedback and search clearing. Do not add browsers, diffs, editors, terminals, or new workspaces as part of this pass.

The migration preserved the existing one chat and two messages. A SQLite backup was created under the ignored `.dev/` directory before applying migration 2. The restarted app uses the ordinary application database and real installed CLIs; the review fixture is not connected to this instance.
